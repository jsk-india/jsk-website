# Troubleshooting

Common problems and their fixes. If you hit something not listed here,
add it after you solve it — future-you will thank present-you.

---

## Local development

### `pnpm install` fails on native modules (sharp, argon2, bcrypt)

Symptoms: build error mentioning `node-gyp`, `sharp`, or `@node-rs/argon2`.

Try:

```bash
pnpm install --force
# or
rm -rf node_modules pnpm-lock.yaml
pnpm install
```

If still failing:

- macOS: `xcode-select --install`
- Linux: `apt-get install build-essential python3`
- Node version too old: `nvm install 20 && nvm use 20`

### `pnpm dev` — "Can't connect to Postgres"

```
Error: connect ECONNREFUSED 127.0.0.1:5432
```

Postgres isn't running.

```bash
docker compose up -d
docker ps    # should show a postgres:16-alpine container "Up"
```

If Docker Desktop isn't running, start it. If the port 5432 is already
taken by a system Postgres, either stop that one or change the port
mapping in `docker-compose.yml`.

### `pnpm dev` — "PAYLOAD_SECRET is using default value"

You forgot to set `PAYLOAD_SECRET` in `.env`. Fix it:

```bash
echo "PAYLOAD_SECRET=$(openssl rand -base64 48)" >> .env
```

### Admin panel is blank / white screen

Usually an importmap issue. Regenerate:

```bash
pnpm payload generate:importmap
```

Then restart `pnpm dev`.

### TypeScript errors after pulling `main`

Someone changed a Payload collection and regenerated types. Sync:

```bash
pnpm install
pnpm payload migrate
pnpm generate:types
```

### "Migration failed" locally

The migration tries to alter your local DB in a way that conflicts with
your existing data (e.g., adds a NOT NULL column to a table with rows).

Options:

- Reset local DB (destroys data):

  ```bash
  docker compose down -v
  docker compose up -d
  pnpm payload migrate
  ```

- Or manually adjust — but usually a fresh local DB is faster than
  fighting migration state.

### Hot reload isn't reloading

Next.js dev server sometimes gets confused after a lot of file changes.

```bash
rm -rf .next
pnpm dev
```

## Production

### Vercel build fails on `payload migrate`

The migration in `src/migrations/` doesn't apply cleanly to prod DB.

1. Check the Vercel deploy log for the exact SQL error.
2. Confirm the previous production deploy is still serving traffic (it
   should be — Vercel only swaps on successful builds).
3. Reproduce locally:

   ```bash
   vercel env pull .env.production.local
   # be VERY careful — this uses your prod DB
   DATABASE_URI=... pnpm payload migrate
   ```

   Or better: restore a prod snapshot into a scratch DB and reproduce there.
4. Fix the migration on a branch, PR, merge, redeploy.

### Vercel build fails on `next build` (TypeScript error)

Someone pushed code that doesn't typecheck. The CI should have caught
this — check why it didn't.

1. Reproduce locally: `pnpm build`.
2. Fix the TS error.
3. Push.

### Site loads but images are broken (404)

Check:

1. **R2 env vars** in Vercel: `S3_BUCKET`, `S3_ENDPOINT`,
   `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`. All present?
2. **`next.config.ts`** `images.remotePatterns` includes your R2 host?
   Currently allows `*.r2.cloudflarestorage.com` — if you use a custom
   domain for R2, add it.
3. Try loading an image URL directly in a browser. Does R2 respond?
4. Cloudflare R2 dashboard → verify bucket is set to public-read.

### Site loads, admin loads, but forms don't submit

1. Open browser devtools → Network tab → submit form → check the
   request.
2. Server action failing? Vercel logs will show the error.
3. If it's an email-send error (`RESEND_API_KEY` missing/invalid),
   forms should still save to DB — the email is best-effort. Check the
   Enquiry / Contact Messages collection to confirm data is landing.

### "Too many database connections" errors

Postgres has a connection cap (e.g., Neon free tier: 100). Vercel's
serverless functions can spawn many. Symptoms: intermittent 500s under
load.

Fixes:

- Use the **pooler connection string** from your DB provider
  (Neon has a `-pooler` endpoint; Vercel Postgres pools automatically).
- Upgrade to a higher tier with more connections.

### Sitemap is empty / missing new pages

Sitemap is generated by `src/app/sitemap.ts`. If you added a new
dynamic route (e.g., a new product category), you may need to add it
to the sitemap logic.

Check by visiting `https://jskindia.in/sitemap.xml`.

### Legacy URL redirect isn't working

Check `src/middleware.ts` — the `REDIRECTS` object. The path must
match **exactly** (query strings are ignored; trailing slash is
tolerated).

To add a new redirect: edit the object, commit, deploy. No migration
needed.

### Admin login says "invalid credentials" but I know they're right

1. Try password reset flow — if reset email arrives, the account exists.
2. If reset email doesn't arrive, check Resend logs (if wired) or
   check the app logs for email-send errors.
3. Last resort: super-admin can reset your password from Users →
   your account → **Reset password** in the admin.

### Everyone is logged out of `/admin` unexpectedly

Someone rotated `PAYLOAD_SECRET`. Not an incident — just log back in.
(If nobody rotated it, that IS an incident — check Vercel env-var
change log.)

### Different languages showing English fallback

The localized field is empty in the target language. Log into `/admin`,
switch to that language, fill the field, save.

If it's supposed to be filled — check that `payload migrate` ran on
the last deploy (it should have — check the deploy log).

## Content / editing

### "I saved my changes but they're not showing up"

Common causes, in order:

1. Wrong language — switch language in admin, verify content is filled.
2. Draft status — set to Published.
3. Browser cache — hard refresh (Cmd/Ctrl + Shift + R).
4. Vercel edge cache — usually clears within seconds; can purge
   manually from Vercel dashboard.
5. Actual bug — reproduce and file an issue.

### "I deleted something by accident"

See [`OPERATIONS.md → Database backup & restore`](./OPERATIONS.md#database-backup--restore).
Restore from a snapshot into a scratch DB, extract the record, re-create
it in prod via `/admin`.

Ideally: catch it within your DB provider's PITR window.

### "I can't upload an image — 'file too large'"

Payload defaults + Vercel limits cap uploads at a few MB. Compress the
image first (Squoosh, TinyPNG). If you regularly upload larger files,
raise the limit in `src/collections/Media.ts` and redeploy.

## Deployment / infra

### "Deploy is stuck 'Building' forever"

- Vercel builds have a 45-min timeout on Pro. If yours is close, check
  for install loops (weird `pnpm install` behaviour).
- Cancel the build from Vercel dashboard, kick off a fresh one.
- If it keeps happening, the culprit is usually a network hiccup during
  `pnpm install`. Retry usually fixes.

### "Preview deploy works, production doesn't"

Env vars differ between preview and production.

Check: Vercel dashboard → Settings → Environment Variables. Make sure
production has every var that preview has.

### "Custom domain shows 'Invalid Configuration'"

DNS isn't pointing at Vercel correctly.

1. Vercel dashboard → Settings → Domains → the domain.
2. Vercel shows you the required DNS records (A / CNAME / ALIAS).
3. Update your DNS at the registrar.
4. Propagation takes minutes to hours. Verify with `dig jskindia.in`.

### "SSL certificate error on the site"

Vercel auto-provisions Let's Encrypt certs. If it fails:

- Check DNS is correctly pointing at Vercel.
- Wait 5 minutes and retry (Vercel retries automatically).
- If persistent, contact Vercel support.
